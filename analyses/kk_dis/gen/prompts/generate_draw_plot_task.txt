## Goal
Generate a ROOT-based plotting script **run/draw_plot_script.py** for THIS analysis.

It reads the fitted weights produced by the draw-weight stage and draws, for each
physical kinematic variable, BOTH plot types (see document/draw_plot_constraints.md §0):

- **Type A — all-partial-wave overlay** (`<var>_weight.png`):
  Data + Fit total + every partial-wave curve on one canvas, with a TLegend listing
  each resonance (and its fit fraction).
- **Type B — single-resonance** (`<var><resonance>_kk_weight.png`):
  Data + Fit total + one partial-wave curve, with the resonance fit parameters and
  the fit fraction annotated in the top-right (see constraints doc §4).

and saves PNGs under `output/pictures/`.

## Required workflow (non-interactive)
1. Read **document/draw_plot_constraints.md** first (the authoritative spec), then the
   analysis-specific inputs:
   - `output/draw/weight.npz` / `output/draw/weight_truth.npz` (from the weight stage;
     keys: `all_mods_wt`, `"<mode>_<basis>"`, `fit_value`, `sum_wt`)
   - `gen/fragments/classification.json` — the actual resonance class names/basis counts
     (mode names like `phif0_kk_BW_flatte980`, basis indices 0..N) and
     `resonances_config.toml` `[resonances.*]` for the resonance labels
   - this analysis's real-data keys (phi_kk, f_kk, plus `[draw].extra_sbc` like
     b123_kk / b124_kk)
   - `run/base_functions.py` / `run/free_params.toml` ONLY as READ reference for parameter
     names/ordering (to build the `kk_<param>_result:` annotation). Do NOT call
     load_data/normalize_data (they tile the MC and pull in jax/scipy).
2. Write **run/draw_plot_script.py** that:
   - is pure numpy + pyROOT (no jax/scipy); imports only from stdlib/numpy/pyROOT
   - loads weights (`np.load(..., allow_pickle=False)` keyed by the weight-stage names),
     and the raw arrays `data/real_data/<var>.npy` (real data) and `data/mc_truth/<var>.npy`
     (MC evaluation sample), applying `sqrt()` to fill (see constraints doc §1.2/§3)
   - discovers present partial-wave keys via regex `^(.*)_(\d+)$` filtered to known
     modes in `MODE_RESONANCES`, skipping missing keys/basis gracefully
   - for each variable, builds TH1D data / fit-total / per-wave histograms, scales
     fit-total and partial waves by `data_size / sum_wt`, draws both plot types on a
     `TCanvas`, adds a TLegend and (for type B) the TLatex parameter/fraction annotation
   - `data_size` = `data/real_data/<var>.npy` length (NOT the tiled base_functions one)
   - `os.makedirs("output/pictures", exist_ok=True)` and saves PNGs per §0 naming
   - defines a `__main__` that runs all variables
3. Run a light smoke (see Context "Smoke test") and write the log to
   **run/draw_plot_test_result.txt**.
4. Finish with a short summary (not the whole .py body):
   task(
     action="finish",
     result=<1-10 lines: path, key functions, smoke status / plots produced>,
     outputs={
       "all": "run/draw_plot_script.py",
       "test_result": "run/draw_plot_test_result.txt"
     }
   )

## Context

### 0) Weight files produced by the weight stage
Keys you can rely on (verify against `run/draw_weight_script.py` if available):
- `all_mods_wt`  : total per-event weight (shape (E,) for this analysis)
- `"<mode>_<j>"` : per-mode, per-basis weight, e.g. `phif0_kk_BW_flatte980_0`,
  `phif0_kk_BW_BW_0..1`, `phif2_kk_BW_BW_0..3`
- `fit_value` / `sum_wt`

### 1) Kinematic variables to plot
sbc keys (actual real-data variables used by this analysis, see stripped_config):
```
all_sbc   = <<stages.config_strip.all_sbc>>
```
Typical real-data keys: `phi_kk`, `f_kk`, plus `b123_kk`, `b124_kk` when
`[draw] extra_sbc` is set in resonances_config.toml.

### 2) Data arrays (do NOT use the tiled base_functions loader)
The plot script reads raw arrays directly:
```python
import numpy as np
data_phi_kk = np.sqrt(np.load('data/real_data/phi_kk.npy'))   # real data (size = data_size)
mc_phi_kk   = np.sqrt(np.load('data/mc_truth/phi_kk.npy'))     # MC evaluation sample
```
`data_size` = the real-data array length. Each weight array from weight.npz has length
equal to the MC evaluation sample size (1200000 for this analysis); for the `b123_kk`/
`b124_kk` extra_sbc the MC weights need to be doubled to match the (doubled) combination
arrays (see the existing run/draw_plot_script.py or constraints doc for the double logic).

### 3) Plot layout (constraints doc §0/§3/§4)
For each `var` in the plot list:
- `hist_data` : fill from `data_<var>` (real data, unweighted)
- `hist_fit`  : fill from `mc_<var>` with weight `all_mods_wt`; `Scale(data_size/sum_wt)`
- for each mode/basis present in the weight keys:
  `hist_comp` : fill from `mc_<var>` with weight `"<mode>_<j>"`; `Scale(data_size/sum_wt)`
- `frac = sum(truth_wt["<mode>_<j>"]) / sum(truth_wt["all_mods_wt"])` (fit fraction
  from the truth sample)
- X/Y axis titles per constraints doc §3 (e.g. `M_#phi` for phi_kk, `M_{KK}` for f_kk,
  `M_{#phi K}` for b123/b124; Y = `Events/<binsize> GeV`)
- **X-axis range must be widened for sharply-peaked (near-delta) variables** (constraints
  doc §2): if the data+mc union relative span `(max-min)/max(|min|,|max|,1)` is tiny
  (e.g. `M_#phi` where every event sits at ~1.019 GeV), do NOT plot the raw min/max —
  ROOT's auto x tick labels (many decimals) overlap into an unreadable clump. Instead use
  `center ± 0.15*max(|center|,1)` where `center=(min+max)/2`; for `M_#phi` this gives
  ~0.87–1.17 GeV (matching the example) and the ticks display cleanly. Leave normal-span
  variables (`M_KK`,`M_#phi K`) at their raw min/max.
- `TCanvas(name, title, 900, 600)`; data markers, fit red line, each partial wave a
  distinct color; TLegend; for type B a TLatex block of `kk_<param>_result:<value>` lines
  plus `fit fraction : <value>`; save named per §0
- return frac (and accumulate the total)

### 4) ROOT availability
pyROOT must be imported as `import ROOT`. Probe runnable pythons in this order
(see document/draw_plot_environment.md):
1. `analyses/kk_dis/.pyroot_envs/rootplot/bin/python` (local, pyROOT 6.40.04 + numpy) — PREFERRED
2. `~/miniconda3/envs/rootenv/bin/python` (remote HEP1, pyROOT 6.40.04 + numpy 2.4.6)
3. local `.venv/bin/python` (usually no ROOT)
If a pyROOT python is available, RUN the script on a small subset/single var as a smoke and
verify PNGs are produced (do NOT settle for syntax-only); otherwise do only:
```bash
python -m py_compile run/draw_plot_script.py
```
and record `ROOT unavailable: syntax-only check` in `run/draw_plot_test_result.txt`.

### 5) Type-B annotation naming (match example; constraints doc §4)
Build the `kk_<param>_result:` lines from each resonance's **propagator shape parameters only**
(not const/theta). Map the `free_params.toml` path suffix to the example label:
- `B_propagator.mass`  → `kk_f<resonance# >_m`  (e.g. phif0_980 → `kk_f980_m`)
- `B_propagator.width` → `kk_f<resonance# >_w`  (e.g. phif2_1270 → `kk_f1270_w`)
- `B_propagator.g_kk`  → `kk_g_kk`
- `B_propagator.rg`    → `kk_rg`
For a resonance with both mass and width (e.g. phif2_*) list both; for phif0_980 list
`kk_f980_m`, `kk_g_kk`, `kk_rg`. Place the TLatex block in the top-right (start y≈0.90, step
0.035) and keep it clear of the legend/curves. Do NOT include const/theta lines.
