## Goal
Interactively generate a likelihood module from the user's LaTeX/formula, save it under
`run/likelihood_function.py`, reuse helpers from `run/base_functions.py`, then run a
smoke test and save the test log.

## Required interactive step
1. First call ask_user to request the likelihood formula. Ask roughly:
   "请输入 likelihood 的 LaTeX/公式说明（可包含 data/mc 项、振幅相干求和、约束项等）。
    若有符号与下面 arg_list / data 名称的对应关系，请一并说明。"
2. Parse the user's answer. If incomplete, ask_user follow-ups.
3. Implement the formula as Python in:
   **run/likelihood_function.py**
4. Run a likelihood smoke test (section "Smoke test") and write the full log to:
   **run/likelihood_test_result.txt**
5. Finish with a short summary (not the full .py body):
   task(
     action="finish",
     result=<1-10 lines: path, key functions, smoke-test status / scalar values>,
     outputs={
       "all": "run/likelihood_function.py",
       "test_result": "run/likelihood_test_result.txt"
     }
   )

## Smoke test (required before finish)
Write and execute a light check (shell). Goals: prove the module imports and returns finite scalars.

Suggested procedure (adapt to available files / devices):
1. Ensure `run/likelihood_function.py` exists and `ast.parse` succeeds.
2. From analysis workdir, run something equivalent to:
   ```bash
   python - <<'PY'
   import sys, traceback
   sys.path.insert(0, "run")
   from base_functions import make_initial_args, np, onp
   import likelihood_function as lf
   # load data: prefer load_data/normalize from gen/fragments if present
   ...
   args, *_ = make_initial_args()  # unpack whatever make_initial_args returns
   # compute data_size from real data length
   val = lf.combined_likelihood(args, data)  # or distributed variant
   print("combined_likelihood =", float(val))
   PY
   ```
3. Capture stdout/stderr + final status into **run/likelihood_test_result.txt**, including:
   - timestamp / command
   - import OK / syntax OK
   - n_args, data_size (if known)
   - printed likelihood scalar(s) (data / mc / combined if available)
   - PASS or FAIL + exception traceback on failure
4. If the test FAILs, fix the .py and re-run until PASS (or ask_user if blocked by missing formula/data).
5. Prefer CPU / small subsets if full mc is too heavy; still use real free_params via make_initial_args.
   Do **not** launch a full minimizer fit in this stage.

## Implementation guidance
- Translate user LaTeX into executable code using **np** (jax.numpy from base_functions).
- Respect classification groups for vectorization when possible.
- Use free_params / parameter_lists for args vs constants.
- Use shape report for broadcasting / einsum axes.
- Keep code compact; no #=== section banners.
- task.finish `result` = short summary only; framework harvests the two files for
  output.all and output.test_result.
