### 这条链是什么

例 1 `ψ→π⁺π⁻π⁰` 的 **ρ 家族**（文档 200–273 行）。

真正要紧的一点：这是**真三体**（末态 3 个粒子），不是"两体 + 一个旁观者"。

| | 例 3（b1pi/rhopi） | 本链 |
|---|---|---|
| 末态 | 4 个（两个两体子系统） | **3 个** |
| 链深度 | 3 | 2 |
| 可用的表象 | 三种都行 | 三种都行（2026-10-21 起）|

### 为什么是三条道

文档的 `U_ρ^μ`（Eq.206–219）是三项之和：

$$
U_\rho^\mu = \epsilon_{\mu\nu\lambda\sigma}p_1^\nu p_2^\lambda p_3^\sigma
  \bigl[B_1(Q_{\psi\rho 3})f^{(\rho)}_{(12)}B_1(Q_{\rho 12})
      + B_1(Q_{\psi\rho 2})f^{(\rho)}_{(13)}B_1(Q_{\rho 13})
      + B_1(Q_{\psi\rho 1})f^{(\rho)}_{(23)}B_1(Q_{\rho 23})\bigr]
$$

ρ 可以由 (12)/(13)/(23) **任意一对** π 组成。框架的模型是"一棵树 = 一条链"，
所以三项就是三条道：

| 道 | 配成 ρ 的对 | 旁观者 |
|---|---|---|
| `u_rho_12` | π⁺π⁻ (1,2) | π⁰ |
| `u_rho_13` | π⁺π⁰ (1,3) | π⁻ |
| `u_rho_23` | π⁻π⁰ (2,3) | π⁺ |

`f^{(ρ)}`（BW 传播子）**不在这三条道里** —— 框架把它放在道外（拟合参数），
三条道自然共用同一个，与文档一致。这一点曾经是"方案 A 不可行"的理由，
2026-10-20 实测证明是误判。

### ⚠️ 树的子节点顺序会整体翻号

这是本链最大的坑。`tree` 里两个子节点的顺序决定了一个整体符号：

```
rho -> (Pip1, Pim2)    ->  +0.191836 i
rho -> (Pim2, Pip1)    ->  -0.191836 i
```

来源是 ε 张量的指标配对顺序，**不是物理差异**。如果三条道的顺序不统一，
相加会得到 `B12 − B13 + B23` 而不是文档的 `B12 + B13 + B23`。

隐蔽之处：每条道单独看都自洽（都能精确写成 `s·c·ε·B_l` 的形式，残差 1e-15），
**只有做置换检验或求和**才暴露。所以本链的验收判据是
`test_ex12_permutation.py` 的置换协变性，而不是"每道能跑通"。

### 判据与实测

| 判据 | 结果 |
|---|---|
| 置换协变性（重标号动量后等于另一条道） | 残差 ≤ 1.5e-15，\|c\| = 1 |
| 逐道 `s·c·ε·B_l(top)B_l(pair)` | 残差 ≤ 4.7e-15，\|c\| = 0.191835806 三道一致 |
| 三条道相加 vs 文档括号 | 残差 5.2e-15，c 为全局常数 |
| `check` 三体拓扑 | ✅ |
| `emit`（cascade）产物 vs 直接调内核 | 逐位相同（0.0） |
| `emit`（cartesian/helicity） | ✅（2026-10-21 补齐 `chains/ex1_pipipi0_rho/`） |
| A1（级联 vs 协变，经 `EPS_A`） | 3.9e-15，三道一致 |

`emit` 原本只有 `helicity_cascade` 能出：`cartesian`/`helicity` 要把
`agent/tensor/chains/<chain>/<channel>.py` 里的**手写**道函数内联，而三体置换道
当时没有手写函数。**2026-10-21 补上了**（`chains/ex1_pipipi0_rho/` 三条），
所以三条路线现在都能出。级联仍然是三体该用的内核（`omega` 对置换族静默错，
见下）。

### 🐛 omega 对"置换族"是**静默错**的（2026-10-20 发现）

这是个真缺陷，而且比"omega 不支持三体"更精确 —— **不是三体的问题，
是"多条道共用不同树"的问题**。

根因：`omega.py` 的 `omega_from_momenta(mom, chain)` 只吃 **base chain**
（`to_chain(spec)`），返回**一份逐道共用**的 `Omega`。三条置换道的树不同
（`rho` 的配对、旁观者都不同），却共用同一份 `Omega` —— 只有和 base 树
一致的那条道对得上。

实测（把 spec 的 basis 换成 omega）：

| 道 | omega vs cascade 残差 | |
|---|---|---|
| `u_rho_12` | 2.4e-16 | ✅ 对（它就是 base 树） |
| `u_rho_13` | 2.96e-01 | ❌ 错 |
| `u_rho_23` | 2.69e-01 | ❌ 错 |

**第一条道对、另两条错** —— 这正是"共用一份 Omega"的指纹。

⚠️ **判据要取对**。两个看起来合理但**错误**的判据：

* ❌「顶层两个子节点都衰变」—— 会把 `ex2_kkpi0_rho` 误判。
  它也是三体（顶层一个是末态），但**只有一条道**、树与 base 相同，
  实测 omega 残差 **3.3e-16（正确）**。
* ❌「深度 ≤ 2」—— 三体的深度恰好是 2，拦不住。

✅ 正确判据：**「是否存在道，其 `[[channel]].tree` 与 base 树不同」**。

`spec.py` 的 `validate` 已按这个判据加拦截（在深度检查之后），
`test_ex12_permutation.py::test_omega_is_silently_wrong_for_permutation_family`
把残差不对称钉住（若哪天修好，测试会失败并提醒反过来写）；
`::test_omega_guard_rejects_permutation_family` 守住 `validate` 的拦截，
并确保它**不会**误伤单道三体（`ex2_rho`）。

**结论**：置换族一律用 `helicity_cascade`。单道三体（如 `ex2_rho`）
用 omega 是**可以**的。
